# 검증 보고서

날짜: 2026-09-18 KST. 환경: Windows, Python 3.11.9, Node 24.19.0, Codex 내장 Chromium 브라우저.

## 서버/순수 로직

기존 접근 검사, V2 개인 기록·비교 검사, 새 맞춤 검색 검사를 실행했습니다. 최초 합산 실행은 상속/모듈 로더에 따른 중복을 포함한 32회 검사로 통과했습니다. 최종 독립 클래스 실행 결과는 `evidence/automated-tests.txt`를 기준으로 합니다.

- C01~C05 L1/L2/L3 인증과 잘못된 사번/비밀번호.
- 게스트·L1·L2·타사에서 문서 및 저장 사례 직접 요청 차단.
- 공개 정적 경계: private/legacy-source/상위 경로/연구원 키 노출 차단.
- 회사·사번별 개인 DB 분리, 허용되지 않는 저장 사례 기록 차단, 삭제.
- 비교 권한: C01-2001만 허용, 각 열의 최대 등급과 자사 필터.
- 연구원 키만으로는 차단, L2+키 차단, 자사 L3+키만 자사 사례.
- 클라이언트가 company/level을 조작해도 discovery 세션 권한 유지.
- 예산 최소 이상/최대 미만, null/음수/NaN/Infinity/역전, 후보0건.
- 날짜 결측·오류·KST 날짜 경계·정확한 마감 시각·시각 없는 날짜.
- HTML escape, 알 수 없는 인용, 유니코드 문자 위치, 저장 답변 해시와 근거 100건 매핑.

## 실제 브라우저에서 확인한 흐름

1. 게스트 HOME의 51건/접수중0건, 공통 디자인, 검색·로그인 진입 버튼.
2. C01 / C01-2001 / 시연 비밀번호로 서버 인증 성공. L1/L2/L3 허용 범위와 회사 이름 확인.
3. 맞춤 탐색 51건, 허용 문서5건, 사용자에서 회사/분야/후보까지 전체 펼침.
4. 저장 OCR 예시 → 올바른 공고 작업 공간 → 답변과 추출 근거 표시.
5. [2] 클릭 후 활성 원문 ID `source-2` 확인.
6. 근거 경로 → 다음 → 현재 단계 `질문` 확인.
7. 지도 17개 시도, 기관명 추정 지역 안내, 부산 선택 후 검색 결과3건, 전체 초기화.
8. C01-2001의 L1/L2/L3 비교 페이지와 공통 질문·자료 범위 표시.
9. 공고 hash URL 새로고침 후 ID 기반 복원.
10. 1920×1080에서 가로 넘침 없음, CTA 하단824px로 화면 내 위치. 1366×768에서 주요 버튼과 읽기 분할 확인.

## 미검증/제약

- 내장 브라우저에 Ctrl+Plus를 보냈으나 DOM viewport/DPR가 변하지 않아 실제125%로 인정하지 않았습니다.
- 별도 Windows 브라우저의 확대 확인은 도구가 현재 URL을 확실히 판단할 수 없어 중단했습니다. 이후 UI 입력을 중단했습니다.
- 마지막 하단 HOME 통합 필터, 요청 순번 처리, fallback 보완은 JS/Python 구문 검사 및 API 검사까지 했으며 최종 UI 재검증은 하지 못했습니다.
- 화면은 작업 대화에 표시했습니다. 독립 PNG 캡처와 로그인/근거/비교 동영상 파일은 제공하지 못했습니다.
- 네트워크 오류/Canvas 실패/OS reduced-motion/탭간 로그아웃의 실제 UI 장애 주입 검사는 하지 않았습니다. 코드에 대체·재시도·정지 처리는 있습니다.
- 프레임 타임/FPS/성능 점수는 실측하지 않았습니다. 성능 수치를 생성하지 않았습니다.
